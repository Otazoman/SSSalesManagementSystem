## 気づいたこと(記録)

- バックエンドのテストを全体で実行すると、在庫の承認の流れのテスト(廃棄・返品・品質区分変更)が時間切れで失敗することがある(単独では成功。負荷による一時的なもの)。
- 管理番号の自動採番(`platform/id/generate-short-code.ts` の `resolveUniqueId`)は「重複を調べてから保存」の順のため、同じ番号が同時に登録されると
  片方が 500 になりうる(日付+乱数4桁のため、起きる可能性は低い。不具合としては挙げていない)。
- 2026-10-03 の修正(BUG-050〜064)で残した影響・未確認のこと(不具合票にはしていない):
  - 納品書 PDF の備考欄の位置(BUG-053)は、自動テストのみで確認。見た目は Staging で確認する。
  - サービス品目(品目マスタの `isService`)は在庫の引当・出荷の一括作成の対象外にしたが、受注1件ずつの出荷画面・進捗確認の出荷残数量は変えていない。
    そのため、サービス品目を含む受注は進捗確認で「出荷完了」にならず、会社設定「売上は出荷済み数量まで」の時はサービス品目を売上にできない。
  - 取引停止の取引先を選択肢から除いたのは、発注・支払の新規登録のみ。ほかの伝票(見積・受注・売上・請求・購買申請・仕入)は未確認。
  - 見積を画面で編集すると、受注明細からの参照(`sourceQuoteItemId`)が空に戻る(以前からの設計。外部キーの制約を避けるため)。
    そのため、受注後に見積を編集すると「見積から受注を作成」の既受注数量が0に戻る(CSV の取り込み直しでは、参照されている明細を入れ替えないので戻らない)。
