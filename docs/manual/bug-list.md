### REQ-005 受注から発注を行えるようにする

- 内容: 今は欠品時のみ発注を作れるが、直送したいケースのために、受注から発注を作れるようにする。
- 要確認: 直送の場合の入荷・出荷の扱い(在庫を通さないか)、発注の納品先(顧客の住所)の設定。
- 今の作り(2026-11-08 にコードで確認): 承認機能が無効なら、発注の画面の「受注欠品から発注を作成」で欠品の明細だけから発注を作れる。
  承認機能が有効なら、受注の欠品から購買申請を作る。発注明細は受注明細とつながり(`salesOrderItemId`)、発注の回答納期が受注明細の
  納期に反映される。受注の承認で自社倉庫の在庫を引き当て、足りない分は欠品になる。発注の納品先は自由入力・営業拠点・倉庫から選べる。
- 直送でぶつかるところ: 受注の在庫の引当・欠品、「売上は出荷実績が必要」「仕入は入荷実績が必要」(出庫・入庫が無い)、納品書(出庫から作る)。
- 方針(2026-11-08 に決定):
  - 受注明細に「直送」の印は持たせない。「受注から発注を作成」で明細を選び、**直送かどうかは発注の単位**で決める。
  - 明細を選ぶ画面は、今ある「受注欠品から発注を作成」(発注)・「受注から選択」(購買申請)の画面に「欠品のみ/すべての明細」の切り替えを
    足して流用する。受注明細とのつながり・回答納期の反映は今の仕組みを使う。
  - 承認機能が有効な場合は、欠品と同じく購買申請を経由する(購買申請から発注を作る時に直送の指定を引き継ぐ)。
  - 直送の完了の記録は **案A**: 直送用の仮の倉庫を用意し、「直送完了」で、発注とつながる入庫(仮の倉庫へ)と受注とつながる出庫
    (仮の倉庫から得意先へ)を同時に確定する(在庫は0のまま。入荷済数量・出荷済数量・在庫の履歴は今の仕組みで動く)。
  - 直送のときも納品書を出せるようにする(案A の出庫から、今の仕組みで作られる)。
- 進め方:
  - 第1段階: 受注から発注を作る(明細の選択の流用、承認機能が有効なら購買申請を経由)、発注の「直送」の指定(DB に列を追加)と
    直送先(受注の得意先の納品先の住所)。発注書に直送先を印字。
  - 第2段階: 直送用の仮の倉庫(在庫照会・引当・出荷指示の対象外)、「直送完了」の操作、受注の在庫の引当・欠品の調整(直送の発注が
    承認されたら、その明細の直送する数量分の引当・欠品を外す。今の引当の仕組みを調べて報告してから進める)、納品書。
- 第1段階の実装(2026-11-08。Staging への反映前):
  - DB: `orders`・`purchase_requests` に `is_direct_shipment`(直送)・`direct_sales_order_id`(直送する受注)を追加(migration 0099)。
    保存の時に、直送なら受注が存在することを確かめる(直送でなければ受注の指定は保存しない)。承認の変更申請でも反映する。
  - 画面: 発注の「受注から発注を作成」・購買申請の「受注から購買申請を作成」(ボタンの名前を変更)に「欠品のみ/すべての明細」の切り替えと
    「直送にする」(受注を1件選んだ時だけ)を追加。すべての明細では、欠品があれば欠品の数量、無ければ受注の数量を初期値にする。
  - 直送の発注は、納品場所に「直送: 得意先名 納品先」(受注で選んだ納品先の住所 → 受注の納品場所 → 得意先の住所の順)を入れる。
    納品場所は今の発注書にそのまま印字される。購買申請から発注を作る時は、直送の指定と直送先を引き継ぐ。
  - 発注・購買申請の画面に「直送」欄(直送の指定がある時だけ出る。印を外せる)。過去の発注の複写では直送を引き継がない。

### TSK-004 倉庫間移動(横持ち)が、出庫と入庫を別々に入力する作りで、つながっていない

- 見つけた日: 2026-11-08(ユーザーの質問「倉庫間を横持ちさせる場合はどう入力するか」から)
- 今の作り(2026-11-08 のコードで確認):
  - 移動元の倉庫で「出荷 > 出庫」に **移動先倉庫** を選んで確定する(移動元の在庫が減る)。移動先の倉庫で「入荷 > 入庫」に **移動元倉庫** を
    選んで確定する(移動先の在庫が増える)。出庫から入庫は作られず、2つの記録はつながっていない。
  - 得意先と移動先倉庫・仕入先と移動元倉庫は、どちらか一方しか指定できない。倉庫間移動では得意先・仕入先が入らないため、納品書は作られず、
    仕入計上の「対象検収」にも出ない(倉庫間移動としては正しい)。発注を選んだ入庫では移動元倉庫を選べない(BUG-078)。
  - 出荷指示・入荷指示(外部倉庫向け)には、倉庫間移動の指定が無い。
- 問題: 入庫の入力漏れに気づけない。輸送中の在庫が分からない。出庫と入庫の数量の食い違いを確かめられない。
- ユーザーの方向性(2026-11-08):
  - 倉庫間移動は、入庫・出庫とは分けた機能(画面・記録)にした方がよいかもしれない。
  - 出荷指示・入荷指示からも、倉庫間移動ができるようにした方がよいかもしれない(外部倉庫との横持ちのため)。
- 検討すること(案):
  1. 倉庫間移動の伝票(移動元・移動先・品目・数量・状態: 出庫済み/輸送中/入庫済み)を新しく持つか、今の出庫・入庫の記録のつながりで表すか。
  2. 移動元の出庫を確定したら「入庫待ち」とし、移動先で入庫する時にそこから選んで数量を消し込む(一部入庫・差異の扱い)。
  3. 外部倉庫が絡む場合(自社→外部・外部→自社・外部→外部)に、出荷指示・入荷指示をどう作るか(指示書の宛先・承認の流れ)。
  4. 在庫照会での輸送中の在庫の見え方、棚卸・在庫評価(会計)での扱い。
  5. 今ある倉庫間移動の記録(出庫の移動先倉庫・入庫の移動元倉庫)の移行。
- DB・画面・承認の流れの変更を含むため、設計を相談してから進める。
